1 (b)(i) [2 marks]

State two drawbacks of using a compiler compared to an interpreter during program development.

1. Slow compilation of large programs: Compiling a large codebase takes time before any code can be tested. With an interpreter, the programmer can run and test partial code immediately without waiting for the entire program to compile.

2. Cannot easily test unfinished code / errors halt everything: If the program has any syntax errors, the compiler will not produce an executable at all. The programmer must fix all errors before running anything. An interpreter stops at the first error it encounters, allowing incremental testing of the code written so far.

  • Larger/complete source code takes time to compile. [1]
  • Program will not run if there are any errors / errors cannot be corrected in real-time / cannot test specific sections easily. [1]

1 (b)(ii) [2 marks]

Explain why high-level language programs might be partially compiled and partially interpreted.

This hybrid approach (used by Java, Python bytecode, .NET CLR) works as follows:

The source code is first compiled into an intermediate form (bytecode or intermediate language) that is platform-independent. This intermediate code is then interpreted (or JIT-compiled) at runtime on the target machine.

Benefits: The intermediate code can run on any platform that has the appropriate runtime environment (interpreter/virtual machine) — without needing to recompile for each target OS/processor. Additionally, the interpreter (JIT compiler) can optimise the machine code specifically for the CPU it's running on at execution time, potentially improving performance.

  • Partially compiled programs can run on different platforms — interpreted when run. [1]
  • Code is optimised for the CPU as machine code is generated at runtime. [1]

3 (c) [2 marks]

Explain the reasons why ROM is used in an embedded system.

ROM (Read Only Memory) is non-volatile — it retains its contents when power is removed. This is essential for embedded systems because:

1. The system's firmware (the program controlling the device) must be available immediately on power-up, without loading from an external source. ROM stores the firmware permanently.

2. Embedded systems often have fixed, unchanging program code that does not need to be modified by the end user. ROM prevents accidental overwriting of the control program.

  • To store data that does not change. [1]
  • Data must be stored when device is without power / to store firmware / boot-up instructions. [1]

Question 4 — Data Integrity (6 marks)

4 (a) [1 mark]

State the difference between data verification and data validation.

Data verification checks that input data is the same as the original source — it ensures the data was transcribed/entered accurately without transcription errors.

Data validation checks that input data is reasonable, complete, and in the expected format — it ensures the data makes sense according to defined rules, but does not check that it matches the original source.

  • Verification checks input matches original; validation checks data is reasonable/sensible. [1]

4 (b) [3 marks]

Describe how a checksum is used to detect errors during data transmission.

A checksum is a value computed from a block of data using a mathematical algorithm.

Before transmission: The sender applies the checksum algorithm to the data block and obtains a checksum value. This value is appended to (transmitted alongside) the data.

After reception: The receiver applies the same algorithm to the received data block and independently calculates its own checksum value.

Comparison: The receiver compares its calculated checksum with the checksum received from the sender. If they match, no error has been detected. If they differ, an error has occurred during transmission (a bit or bits have changed), and the receiver requests a retransmission.

  • Checksum calculated from data before transmission. [1]
  • Checksum transmitted with the data. [1]
  • Receiver recalculates and compares — match = no error, mismatch = error detected. [1]

4 (c) [2 marks]

Describe two validation methods (other than presence check) that can be used to validate non-numeric data.

1. Format check: Verifies that the data matches a required pattern or format. For example, an email address must contain '@' and a domain; a date must follow DD/MM/YYYY format. Ensures only expected characters and structures are accepted.

2. Length check: Checks that the data contains the correct number of characters. For example, a postcode must be a specific length; a username must be between 5 and 20 characters. Rejects inputs that are too short or too long.

Also valid: look-up check (checks if value exists in a predefined list); type check (confirms data is the right data type).

  • Format check — data must match required format / only expected characters. [1]
  • Length check — correct number of characters. [1]

Question 5 — Database GARDEN (11 marks)

Tables: OWNER(OwnerID, FirstName, TelephoneNo, TreeID, TreePosition) · TREE(TreeID, ScientificName, MaxHeight, FastGrowing)

5 (a) [3 marks]

The database is not in 3NF. Explain how it can be normalised to 3NF.

The problem is that OWNER contains TreeID and TreePosition — an owner can have many trees, creating a many-to-many relationship between OWNER and TREE stored (badly) within a single table. This violates normalisation because one owner record cannot store multiple trees without repeating data.

Solution:

1. Remove TreeID and TreePosition from the OWNER table (they don't belong there — they describe a relationship, not a property of the owner).

2. Create a new linking table to resolve the many-to-many relationship between owners and trees: for example, OWNER_TREE(OwnerID, TreeID, TreePosition).

3. The composite primary key of the linking table is (OwnerID, TreeID).

Now OWNER holds only owner details (OwnerID as PK), TREE holds only tree species details (TreeID as PK), and OWNER_TREE records which trees belong to which owners and their positions.

  • Removing the many-to-many relationship between Owner and Tree. [1]
  • Removing TreeID and TreePosition from OWNER table. [1]
  • Creating a linking table with OwnerID, TreeID, TreePosition and appropriate composite primary key. [1]

5 (c) [1 mark]

State what is meant by a candidate key in a relational database.

A candidate key is an attribute (or minimal set of attributes) that could serve as the primary key — i.e., it uniquely identifies each row in the table and is minimal (no subset of it alone is sufficient). A table may have multiple candidate keys; the designer chooses one as the actual primary key.

5 (d)(i) [2 marks]

Describe, using an example, what is meant by a data dictionary.

A data dictionary is a repository that stores metadata — data about the data stored in the database. It describes the structure of the database rather than the actual data values.

Example: For the TREE table, the data dictionary would record: field names (TreeID, ScientificName, MaxHeight, FastGrowing), their data types (VARCHAR, VARCHAR, DECIMAL, BOOLEAN), which field is the primary key (TreeID), validation rules (MaxHeight must be positive), and relationships to other tables.

  • Stores metadata about the database / description of data stored. [1]

5 (d)(ii) [2 marks]

Describe what is meant by a logical schema.

A logical schema is an overview of the database structure that models the organisation and relationships between tables. It represents how the data is logically organised — typically shown using methods such as an Entity-Relationship (E-R) diagram — showing tables, their attributes, primary/foreign keys, and the relationships between tables.

The logical schema is independent of any specific DBMS or physical implementation — it describes what is stored and how entities relate, without specifying how data is physically stored on disk.

  • Overview of database structure / models the situation using ER diagram. [1]
  • Independent of any particular DBMS. [1]

Question 6 — Network Security & Sound (7 marks)

6 (a)(i) [2 marks]

Explain how a digital signature ensures the email is authentic.

A digital signature works using public-key cryptography:

1. The sender passes the email message through a hashing algorithm to produce a fixed-length message digest (hash).

2. The digest is encrypted with the sender's private key — this encrypted digest is the digital signature, attached to the email.

3. The recipient receives the email and the signature. They decrypt the signature using the sender's public key. If the public key successfully decrypts it, the signature could only have been created by the holder of the private key — authenticating the sender's identity.

4. The recipient also hashes the received message and compares it with the decrypted hash. If they match, the message has not been altered in transit.

  • Message put through hashing algorithm to produce a digest; digest encrypted with sender's private key. [1]
  • Signature can only be decrypted with the matching sender's public key — proves authenticity. [1]

6 (a)(ii) [3 marks]

Describe how a firewall protects the data on the computer.

A firewall sits between the computer (or network) and external networks (such as the internet), examining all incoming and outgoing network traffic.

It operates according to a defined set of rules (an allow-list and/or deny-list) that specify which types of traffic are permitted. These rules may be based on:

• IP addresses: Block traffic from known malicious IP addresses.

• Ports: Allow only traffic on specific ports (e.g. port 443 for HTTPS) and block all others.

• Protocols: Permit certain protocols and deny others.

Any packet that does not meet the permitted criteria is blocked before it can reach the computer. This prevents unauthorised access attempts, stops malware communicating with external command servers, and filters out suspicious traffic.

  • Monitors incoming and outgoing packets / traffic. [1]
  • Checks against allow/deny list of IP addresses / rules for acceptable data / ports. [1]
  • Blocks transmissions that do not meet criteria. [1]

6 (b)(i) [2 marks]

Explain the effect of increasing the sampling rate on the accuracy of a sound recording.

The sampling rate is the number of times per second the analogue waveform is measured. A higher sampling rate means measurements are taken more frequently — the digital representation captures more detail of how the waveform changes over time. The resulting digital waveform more closely resembles the original analogue signal, reducing the loss of information between samples. This improves accuracy, particularly for high-frequency sounds, and reduces quantisation-related artefacts.

  • Improves accuracy of the sound file. [1]
  • Digital waveform more closely resembles the analogue original / quantisation errors reduced. [1]

Question 8 — Bitmap Images (6 marks)

8 [2 marks]

The bitmap image has resolution 4096 × 4096 pixels and 24-bit colour. It is displayed on a 1920 × 1080 monitor. Tick boxes to show the effect of each action on the image file size.

File size = pixels × bits_per_pixel. The file size depends on the image's own resolution and colour depth, NOT on the monitor's display resolution.

• Change colour depth from 24 to 16 bits/pixel: Fewer bits per pixel → file size decreases.

• Change screen resolution to 1366 × 768: The monitor resolution changes how the image is displayed, but the image FILE size is unchanged (the file still has 4096×4096 pixels at 24 bits each).

• Change colour of rectangle from black to red: The pixel colours change, but the number of pixels and bits per pixel remain the same. File size = no change. (In an uncompressed BMP the file size is exactly the same; in a compressed format it might vary slightly, but the question implies standard calculation.)

  • Correct row 1 (colour depth 16 bpp → Decreases). [1]
  • Correct rows 2 and 3 (screen resolution → No change; colour → No change). [1]

8 (b) [2 marks]

State two benefits of creating a vector graphic instead of a bitmap image.

1. Scalable without quality loss: Vector graphics can be enlarged to any size without pixelation, because they are described mathematically (as lines, curves, and shapes). Bitmaps lose quality and become pixelated when enlarged beyond their original resolution.

2. Generally smaller file size (for many graphics): Vectors store mathematical descriptions of shapes rather than every individual pixel, which is typically more efficient for diagrams, logos, and illustrations compared to equivalently-sized bitmaps.

  • Can be enlarged without pixelation / loss of quality. [1]
  • Individual components can be edited / generally smaller file size. [1]

Describe the social impact of using facial recognition software to identify individuals in an airport.

Positive impacts: Individuals may feel safer in the airport, knowing that known criminals or terrorists can be quickly identified. The technology can speed up boarding processes (faster identity checks without manual document inspection), improving passenger experience.

10 (b)(ii) [3 marks]

Describe the role and function of the router in the network.

The router serves as the gateway between the LAN and the internet. It performs several key functions:

1. Packet forwarding: Receives data packets from devices on the LAN (or from the internet) and forwards them toward their destination using the IP address in each packet's header.

2. Routing: Consults its routing table to determine the most efficient path for each packet. It stores and updates routing information about reachable networks.

3. NAT (Network Address Translation): Assigns private IP addresses to devices on the LAN and provides the LAN with a single public IP address for communicating with the internet. This maps multiple private addresses to one public address.

  • Receive packets and find the destination using IP address. [1]
  • Forward packets to destination / find most efficient path / maintain routing table. [1]
  • Assign private IP addresses / provide LAN with public IP address / act as gateway. [1]
